## 요약

- 주소: **https://lc-moon.github.io/26_2_Hackathon/**
- `main`에 push하면 `.github/workflows/pages.yml`이 `seoul_vworld.html`을 `index.html`로 올린다. 브이월드 키는 저장소 Secret `VWORLD_KEY`에서 배포 때만 넣는다(저장소에는 자리표시 그대로)
- 휴대폰으로 열면 "PC 크롬에서 봐 주세요" 안내가 먼저 뜬다. "그래도 열기"를 눌러야 지도를 불러온다
- README 맨 위에 배포 주소와 스크린샷 두 장(`docs/screenshot_tow.jpg`, `docs/screenshot_crash.jpg`)을 넣었다

## 판단과 근거

- **GitHub Pages를 골랐다.** 서버·DB가 없는 HTML 파일 하나라 정적 호스팅이면 충분하고, 무료이며 한 번 올리면 따로 관리할 것이 없다(사용자 요청: 무료, 신경 쓸 일 없이 계속 유지)
- **키는 Secret으로 넣었다.** 이 저장소는 "실제 키를 커밋하지 않는다"는 규칙이 있다. 배포된 페이지에서는 키가 보이지만, 브이월드 키는 등록한 서비스 URL에서만 동작한다
- **휴대폰은 막지 않고 안내만 한다.** 화면이 PC 기준이라 휴대폰에서는 깨지지만, 그래도 보고 싶은 사람은 볼 수 있게 했다
- 처음 만든 안내는 휴대폰 크기에서 화면 밖으로 밀려났다. PC용 패널이 고정 폭이라 화면 폭이 넓어졌기 때문이다. 안내가 떠 있는 동안 다른 요소를 숨겨(`body.mobile-wait`) 고쳤다
- 첫 배포 두 번은 Secret이 없어 실패했다(워크플로가 일부러 멈추게 해 두었다). Secret을 넣은 뒤 세 번째에 성공했다

## 확인한 것

- 배포 주소를 1920×1080 크롬(Playwright, 헤드리스)으로 열었다. 진단 로그가 모두 정상이었고(브이월드 스크립트, Cesium 1.99 뷰어, 비행차량 3대와 목격자 모델 로드), 약 48초 뒤 평시 시나리오가 자동 재생됐다
- 스크린샷은 같은 방법으로 시나리오 ③의 12초(추돌)와 44초(견인 이송) 장면을 찍었다
- 휴대폰 안내는 로컬 서버에서 375×812 휴대폰 흉내 모드로 열어 봤다. 안내가 화면 가운데에 뜨고, 버튼을 누르면 지도를 불러오기 시작했다. PC 크기에서는 안내가 뜨지 않았다

## 확인하지 못한 것

- 실제 휴대폰에서 열어 보지 않았다(브라우저의 휴대폰 흉내 모드로만 확인)
- 배포 주소에서의 프레임 속도는 재지 않았다
