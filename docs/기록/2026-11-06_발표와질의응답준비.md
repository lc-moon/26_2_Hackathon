# 2026-11-06 · 발표와 질의응답 준비

> 발표일. 발표(5분 + 질의 5분)를 마쳤고 **대상(1등)을 받았다.** 발표 도중·직후에 나올 수 있는 질문을 대비하며 근거를 확인했다.
> 이 기록은 작업 중 대화를 보고 썼다. 발표 현장(질문 내용, 점수, 심사평)은 대화에 없어 적지 않았다.

---

## 요약

- 우리 앱의 API·스택, 애니메이션 구현 방식, UI 구성의 근거를 정리했다
- 다른 조에 "기존 시스템을 참고해 메뉴를 선택했는가"라는 질문이 나온 것을 보고, 우리에게도 올 질문으로 보고 근거를 조사했다
- 실제 119 상황관제 화면은 공개 자료에서 찾지 못했다. 대신 공개된 표준과 업무 흐름을 찾아 **만든 뒤의 대조**로 근거를 만들었다
- **결과: 대상(1등)**

## 한 일

### 스택과 API 정리
- 완제품: 브이월드 3D 지도 API 3.0(내장 Cesium 1.99), jQuery 3.6.0, Google Fonts. 이전 시도는 MapLibre+OpenFreeMap(`seoul_sim.html`), Cesium 1.120+OpenStreetMap(`archive/golden3d.html`, 실패)
- 시나리오 애니메이션: 순수 JavaScript로 시간 함수·보간·키프레임을 쓴 연출. 물리 엔진이나 실제 데이터를 쓰지 않았다는 점을 답변으로 정리했다 (`구현_이해하기.md`)

### 기존 시스템 참고 여부
- 솔직한 결론: 레이아웃은 UAM 구조 지원 예시 웹앱을 참고했다. 실제 119 화면은 보지 못했다
- "공개가 안 됐다"고 단정했다가, 검색해 보니 **화면은 못 찾았지만 업무 흐름과 기능은 공개**되어 있어 답변을 고쳤다. 못 찾은 것과 없는 것은 다르다

### 표준 문서 확인
받은 링크의 PDF를 읽어 보니 **스마트도시표준화포럼 표준 SSF-ST-T-0017 "119 긴급출동 지원서비스 요구사항"**(2018-11-27 제정)이었다.
- 119 종합상황실이 스마트도시 통합운영센터에서 CCTV 영상을 받아 출동 차량에 전달하는 서비스의 요구사항
- 이벤트 모니터링, 소방차량 이동위치 목록, 상황이력·통계, GIS(OGC), WGS84 좌표계
- 고도·층·3D 요구사항은 없다. UI 목록은 별도 표준 SSF-ST-T-0019를 참조하라고 되어 있지만 찾지 못했다

### UI 근거표
구조대의 질문 순서(무슨 사고 → 어디 → 누가 위험 → 어떻게 가나 → 주변 안전)로 패널을 나눴다는 설명을 중심으로, 패널별로 대조한 근거(표준 항목 번호, 119 접수 절차, 정부 정밀측위 보도)를 표로 만들었다. **우측 탑승자 패널은 기존 119 근거가 없고 가정**이라는 점을 그대로 적었다. `docs/발표.md`
