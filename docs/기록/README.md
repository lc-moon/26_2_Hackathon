## 흐름 요약

**제작일(11/5) — 하루 안에 만들고 바꾸고 올렸다**
이전 대화에서 만든 서울 3D 공중 사고 애니메이션 위에 오후 8시경부터 119 상황실 화면을 얹었다. 이후 피드백이 올 때마다 고치고(패널 줄이기 → 충돌·견인 → 시나리오 3종 → 가독성·효과 → 레이아웃), 고치기 직전마다 `archive/`에 백업을 남겼다. 21시 46분에 서버에 올렸고, 밤에는 발표자료를 만들며 사실 확인을 거쳐 앱의 표기를 정정하고 다시 올렸다. 백업 파일 이름과 시각이 곧 작업 순서다.

**발표일(11/6) — 질문에 답할 근거를 만들었다**
발표를 마쳤고 대상을 받았다. 질문 대비에서는 "확인하지 못한 것은 못 했다고 말한다"를 지켰다. 실제 119 화면은 못 찾았다고, 센서와 수치는 가정이라고, UI는 만든 뒤에 공개 표준과 대조했다고 답하는 쪽으로 정리했다.

**문서화(11/9)**
끝난 프로젝트를 다시 볼 수 있게 저장소 양식으로 정리했다.

## 이 프로젝트에서 배운 것

- **전제를 의심하는 것**이 가장 큰 개선이었다. "기존 GPS는 2D"라는 우리의 가정이 틀렸다는 것을 발표 직전에 알았고, 그것을 숨기지 않고 발표의 한 장으로 만들었다
- **피드백 때마다 직전 백업을 남기는 습관**이 되돌릴 수 있는 안전망이 됐다(작업 중 만든 백업 10개)
- **수치는 눈이 아니라 계산으로**: 차량 겹침은 계산으로 찾았고, 비교 숫자는 기준이 같은지 따졌다("14분 vs 23분"은 기준이 달라 "5분 vs 19분"으로 바꿨다)
- **측정하지 못한 것은 못 했다고 쓰기**: 렉을 줄였다고 말하지 않고 "줄이려고 이런 것을 바꿨고 측정은 못 했다"고 적었다
