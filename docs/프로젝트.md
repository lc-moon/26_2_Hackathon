## 1. 프로젝트 개요

**한 줄**: 하늘 위 사고, 위치부터 정확하게. 비행차량 사고에서 **높이(Z)까지 포함한 위치를 자동으로 구조대에 전달**하면 구조가 어떻게 달라지는지 서울 3D 지도 위에서 시뮬레이션한다.

**팀 슬로건**: 하늘의 사고에도, 구조의 사각지대는 없도록.

**핵심 메시지**: 사고 위치를 "어디에서"뿐 아니라 "몇 층 높이에서"까지 알면 구조 시간이 줄어든다. 그 정보가 없으면(시나리오 ②) 골든타임을 놓칠 수 있다.

**산출물**

## 2. 문제의식과 사실 확인

### 처음 가설과 정정

처음에는 "기존 GPS는 2D(X, Y)만 알려 주고 Z축 정보가 없으니, Z축을 넣으면 사고를 막을 수 있다"고 생각했다.
**이것은 일부 틀렸다.** GPS 신호는 위도·경도뿐 아니라 고도까지 계산한다(수직 정확도는 보통 수평보다 나쁘다).
실제 문제는 **신고·지도·관제 체계가 수평 위치 중심이라 높이가 구조대에 자동으로 전달되고 입체로 보이는 데 한계가 있다**는 점이다.
이 정정을 발표의 한 장(AI를 믿지 않고 확인했다)으로 삼았다. 앱 안의 "2D GPS" 표시도 "위도·경도"로 고쳤다.

### 확인한 근거

| 근거 | 내용 | 확인 정도 |
|---|---|---|
| 디지털투데이 2026-06-23 보도 | 과기정통부·소방청이 대전에서 기지국·Wi-Fi·블루투스·기압 신호로 **층(높이) 정보를 주는 정밀측위**를 시범했다. 기존 기지국+GPS 방식으로는 실내 위치와 층 확인이 어려웠다. 오차 약 30m → 15m, 후속 연구는 2027년까지 10m·건물 단위를 목표로 하며 긴급구조 표준 시스템 추가를 추진 중 | 본문 확인 |
| 스마트도시표준화포럼 표준 SSF-ST-T-0017 "119 긴급출동 지원서비스 요구사항" (2018-11-27 제정) | 119 종합상황실이 스마트도시 통합운영센터에서 CCTV 영상을 받는 서비스. 이벤트 모니터링(유형·날짜·진행상황), 소방차량 이동위치 목록, 상황이력·통계, GIS(OGC 표준)와 WGS84 좌표계. **고도·층·3D 요구사항은 없다.** UI 목록은 별도 표준 SSF-ST-T-0019를 참조하라고 되어 있으나 찾지 못했다 | PDF 본문 확인 |
| 119 접수 업무 흐름 | 신고접수 → 신고자 위치 등 기본 정보 표시 → 예고지령 → 출동대 자동 편성 → 재난지점 결정 → 출동지령. 관제는 관제처리·사건 진행 상황관리·추가 출동대 편성·관제 현황 조회 | 검색 요약만 확인 (소방 관련 학회 자료, KoreaScience 논문) |
| 신고 위치정보 문제 | 이동전화 신고자의 위치정보가 부정확하고 재난 위치를 설명하기 어려운 것이 119 접수의 큰 문제로 지적됨 | 검색 요약만 확인 (KoreaScience 논문) |

- **실제 119 상황관제 화면은 공개 자료에서 찾지 못했다.** 비공개가 확실하다는 뜻은 아니다. 나라장터의 제안요청서나 교육 자료에 있을 수 있다.
- "119가 고도를 못 받는다"고 단정하지 않는다. 확인한 것은 "높이·층 식별에 한계가 있고 정부가 개선 중"까지다.

## 3. 시나리오 명세

내부 시간 `t`(초)로 정의하고, 재생은 3배속이라 실제 재생 시간은 `t ÷ 3`이다. 화면의 "가정 시간"은 별도 함수로 매긴다.

### ③ 3D 좌표 자동 전송 (T = 54초, 재생 18초)

| t(초) | 가정 시간 | 장면 |
|---|---|---|
| 0–12 | — | A(동쪽으로)·B(북쪽으로) 정상 비행, 교차 항로 접근 |
| 12 | 0분 | **공중 추돌.** A의 앞머리가 B의 옆면에 닿고, 약 28m 이격하며 튕겨 멈춤. 둘 다 기동 불가, 추락 없음 |
| 14 | 약 1분 | 3D 좌표 자동 전송, 119 구조 요청 접수 |
| 17 | 1분 | 구조 비행차량 출동(구조 거점 출발) |
| 22 | — | 상부 접근 경로 확정. 두 기체 위(고도 240m)를 지나 도킹 지점으로 |
| 30 | 5분 | 도킹. 구조차–케이블–가로대–양끝 팔–두 기체의 `-[` 대형을 이룸 |
| 34 | 6분 | 안전 착륙지로 이송 시작 |
| 48–50 | 14분 | 착륙. 결과 화면 "2차 사고 없이 안전 구조" |

### ② 높이 정보·자동 신고 없음 (T = 54초)

| t(초) | 가정 시간 | 장면 |
|---|---|---|
| 12 | 0분 | 추돌. 자동 신고 없음, 119는 사고를 모름 |
| 19 | 3분 | 지상 시민(목격자)이 신고, 위치·높이 불명확 |
| 23 | 5분 | 119 출동 지령, 지상 위주 수색 (구조차는 70m 고도로 지상 수색) |
| 30 | 8분 | 탑승자 B-1 심정지 |
| 38 | 13분 | 구조대 현장 도착, 상공의 기체를 발견 못 함 |
| 44 | 17분 | 목격자 재신고, 상공 확인 |
| 48 | **19분** | 구조 비행차량이 두 기체 위로 접근 (이미 늦음). 시계는 19:00에서 멈춤 |
| 52 | 약 22분 | 소생 실패, 사망 확인. 결과 화면 "골든타임을 놓쳤습니다" |

이 시나리오에서는 좌표의 Z 값, 3D 거리 비교, 고도차 항목을 화면에서 뺀다(위도·경도만 표시).

### ① 평시 운항 (T = 36초, 반복)

A·B·119 순찰 차량이 서로 겹치지 않는 구역에서 정상 운항. 119 신고 0건, 탑승자 지표 정상. 사이트를 켜면 기본으로 재생된다.

## 5. 화면 구성 (119 상황실 스타일)

- 상단: 제목, 시나리오 탭 3개, 시연 바(재생·처음부터·슬라이더·시간), 시계
- 좌: 사고 개요(상태 알약·한 줄 원인) / 실시간 3축 좌표(A·B·구조차의 X·Y·Z·속도·방위) / 자동 기록 타임라인(최근 3건)
- 우: 탑승자 3명(심박·산소포화도·혈압, 심전도, 위험도 순 정렬, 구조 우선순위 번호)
- 하단: 초정밀 3D 측위(정확도, 수색 고도 범위 비교) / 출동·접근(거리, 도달 시간, 구조대·119·병원) / 현장 2차 위험(A–B 이격, 고도차, 구조차 거리)
- 지도 위: 차량 이름표(HTML 오버레이), 경로선, 목적지 표시, 3D 모델, 견인 케이블
- 강조 효과: 추돌 섬광·화면 흔들림, 중앙 큰 문구, 붉은 테두리 깜빡임, 위험 카드 깜빡임, "골든타임 초과" 시계

패널 구성의 근거와 질의응답 대비는 `발표.md`. 색은 119 구조 느낌의 레드(#D93025)를 주색으로, 흰색·연회색 카드, 주의 오렌지(#E37400), 안전 그린(#188038), 정보 블루(#1A73E8).

## 6. 데이터와 외부 서비스

실제 데이터는 쓰지 않는다. 좌표·시간·생체신호는 모두 시간 함수로 만든 가상값이다. 외부에서 받아 오는 것은 아래뿐이다.

| 항목 | 용도 |
|---|---|
| 브이월드 3D 지도 API 3.0 (`map.vworld.kr`, `cdn.vworld.kr`, `2d.vworld.kr`) | 3D 건물·항공영상·지형·지명. API 키 필요(활용 API: 3D 지도 API) |
| jQuery 3.6.0 (`code.jquery.com`) | 브이월드 구동용 |
| Google Fonts (Noto Sans KR) | 글꼴 |

브이월드 안에 들어 있는 **Cesium 1.99**가 3D를 그린다. 이전 시도는 MapLibre+OpenFreeMap(`seoul_sim.html`)과 Cesium 1.120+OpenStreetMap(`archive/golden3d.html`, 실패).
